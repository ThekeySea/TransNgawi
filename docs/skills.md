# TransNgawi — Design & UI Skills

## 1. Design North Star

> Bold enough to be remembered, restrained enough to be trusted.

Core principle:
> Bold Core, Quiet Structure.

TransNgawi should feel:
- youthful;
- confident;
- modern;
- approachable;
- professional;
- affordable;
- comfortable.

It should not feel:
- luxury hotel;
- stiff corporate;
- generic transport template;
- neon tech;
- glassmorphism showcase.

## 2. Visual Hierarchy

Every screen must have:
1. primary task;
2. primary information;
3. supporting information;
4. secondary actions.

Do not make every element visually loud.

## 3. Color

Orange is the primary brand/CTA color.

Orange must not cover the entire interface.

Use:
- neutral surfaces for structure;
- dark color for strong contrast;
- semantic colors for states;
- orange selectively for brand and action.

Avoid:
- uncontrolled gradients;
- neon glow;
- excessive color variety.

## 4. Typography

Use a strong, highly legible sans-serif system.

Hierarchy should be obvious through:
- size;
- weight;
- line height;
- spacing.

Avoid making headings tiny.

Avoid oversized headings that destroy layout usability.

## 5. Spacing Tokens

Base scale:

Prefer tokens over arbitrary numbers.

## 6. Container

Target content width:
- approximately 1200–1280px on desktop.

Mobile uses appropriate horizontal padding.

## 7. Radius

Use restrained rounding.

Recommended conceptual levels:
- small controls: 8–12px;
- cards: 12–20px;
- large feature surfaces: 20–28px.

Do not round every nested element.

## 8. Shadows & Borders

Use subtle depth.

A component should normally use either:
- border;
- shadow;
- surface contrast;

rather than stacking all three aggressively.

## 9. Buttons

Primary:
- orange;
- high contrast;
- clear action text.

Secondary:
- neutral/outlined/appropriate brand treatment.

Every button needs:
- default;
- hover;
- active;
- focus;
- disabled;
where applicable.

## 10. Forms

Forms are product UI, not decoration.

Requirements:
- labels;
- clear controls;
- sensible grouping;
- visible focus;
- validation;
- useful error messages;
- mobile usability.

## 11. Cards

Cards must have a reason to exist.

Avoid:
- card inside card inside card;
- excessive shadows;
- identical visual treatment for unrelated content.

## 12. Homepage Visual Contract

### Hero
- full bleed;
- bus photo;
- overlay text;
- strong readability;
- no internal card.

### Booking Widget
- visually distinct from background;
- overlaps Hero and next section;
- strongest functional surface;
- highest relevant stacking layer;
- balanced spacing below.

### Important Travel
- four concise information cards;
- deliberate whitespace;
- no excessive decoration.

### About CTA
- one horizontal rectangle;
- image left;
- content right;
- one CTA;
- responsive stacking on mobile.

### Footer
- dark.

## 13. No Eyebrow Rule

Do not add decorative small text above page titles.

Functional labels are allowed.

## 14. Photography

Bus imagery should communicate:
- movement;
- comfort;
- real travel;
- credible transportation.

Prefer strong crops and purposeful placement.

Do not use generic stock imagery that makes the brand feel fake.

## 15. Responsive Design

Do not simply shrink desktop.

Recompose:
- navigation;
- booking form;
- grids;
- CTA;
- typography;
- spacing.

Mobile must remain intentional.

## 16. Accessibility

Minimum:
- semantic HTML;
- keyboard navigation;
- visible focus;
- sufficient contrast;
- meaningful labels;
- alt text;
- reduced-motion support.

## 17. Admin Visual Language

Admin is operational software.

Prioritize:
- dense information;
- clear status colors;
- tables;
- filters;
- predictable actions;
- readable typography.

## 18. Element Creation Protocol

Before creating any visual element:

1. What user task does it support?
2. What information does it communicate?
3. What is its hierarchy?
4. Does it belong to the design system?
5. What are desktop/mobile states?
6. What happens on hover/focus/loading/error?
7. Does it need to exist at all?

If the answer to #1 is unclear, do not add the element.

## 19. Anti-Patterns

Do not use:
- random gradients;
- excessive glassmorphism;
- neon borders;
- ornamental blobs everywhere;
- giant empty spaces;
- tiny text;
- fake metrics;
- unnecessary sections;
- excessive animation;
- decorative eyebrows;
- card stacking without hierarchy.

## 20. Quality Bar

The final interface should look deliberately designed, not generated by accumulating components.

References can inspire:
- composition;
- hierarchy;
- interaction patterns;
- editorial rhythm.

Do not clone another company's visual identity.
